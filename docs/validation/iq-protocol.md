# Installation qualification protocol

Verifies that Dioptra is installed from the vendor's release, unaltered, on a supported
system, and that the installed build identifies itself as the version released.

Execute per computer, or once per approved disk image and record the computers it is
deployed to. Record every result in the execution record (section 6). Deviations are
handled as in [oq-protocol.md](oq-protocol.md), section 5.

## 1. Prerequisites

| # | Item | Record |
|---|---|---|
| P1 | Approved validation plan and change request for this installation | Document IDs |
| P2 | Version to install, as approved (for example `0.4.0`) | Version |
| P3 | Supported operating system: Windows 10 or 11 (x86-64); macOS 10.15 or later (Apple silicon or Intel); Linux x86-64 with glibc 2.35 or later (AppImage, deb or rpm) | OS, version, architecture |
| P4 | Computer name or asset ID; tester's name | — |
| P5 | Dioptra Lab license key, for the records controls and the automated OQ | Key holder (not the key) |

## 2. Obtain the release

Releases are published at `https://github.com/ZahakJ/dioptra/releases`, one per version
tag `vX.Y.Z`. Each release holds the installers for every platform and `SHA256SUMS.txt`,
the SHA-256 of every file of the release, generated by the release workflow from the
uploaded files (`.github/workflows/release.yml`).

| File | Platform |
|---|---|
| `Dioptra_<version>_x64_en-US.msi` | Windows, per-machine install (administrator) |
| `Dioptra_<version>_x64-setup.exe` | Windows, per-user install |
| `Dioptra_<version>_aarch64.dmg` | macOS, Apple silicon |
| `Dioptra_<version>_x64.dmg` | macOS, Intel |
| `Dioptra_<version>_amd64.AppImage` | Linux, any distribution |
| `Dioptra_<version>_amd64.deb` | Debian, Ubuntu |
| `Dioptra-<version>-1.x86_64.rpm` | Fedora, RHEL |

Download the installer for the platform and `SHA256SUMS.txt` from the release page of the
approved version, not from "latest".

## 3. Verify the checksum

Compute the SHA-256 of the downloaded installer and compare it with its line in
`SHA256SUMS.txt`. They must be identical.

Windows (PowerShell):

```powershell
Get-FileHash .\Dioptra_0.4.0_x64_en-US.msi -Algorithm SHA256
Select-String -Path .\SHA256SUMS.txt -Pattern 'Dioptra_0.4.0_x64_en-US.msi'
```

macOS:

```sh
shasum -a 256 Dioptra_0.4.0_aarch64.dmg
grep 'Dioptra_0.4.0_aarch64.dmg' SHA256SUMS.txt
```

Linux:

```sh
sha256sum --check --ignore-missing SHA256SUMS.txt
```

`sha256sum --check` prints `OK` for each file present. Any other result is a deviation: do
not install.

## 4. Install

**Windows.** Run the `.msi` as an administrator (per-machine) or the `-setup.exe` (per user).
The installers are not signed with a Windows code-signing certificate; SmartScreen may
warn. Record the warning and continue with **More info → Run anyway** only when the checksum
in step 3 matched.

**macOS.** Open the `.dmg` and drag Dioptra to Applications. The app has an ad-hoc signature
and is not notarized (see [macos-gatekeeper.md](../macos-gatekeeper.md)). On first launch,
macOS 14 and earlier: Control-click the app, **Open**, **Open**. macOS 15 and later: open it
once, then **System Settings → Privacy & Security → Open Anyway**. Verify the signature:

```sh
codesign --verify --deep --strict --verbose=2 /Applications/Dioptra.app
```

Expected: `valid on disk` and `satisfies its Designated Requirement`.

**Linux.** AppImage: `chmod +x Dioptra_0.4.0_amd64.AppImage`, then run it. deb:
`sudo dpkg -i Dioptra_0.4.0_amd64.deb`. rpm: `sudo rpm -i Dioptra-0.4.0-1.x86_64.rpm`.

## 5. Post-installation checks

| # | Step | Expected result |
|---|---|---|
| IQ-1 | Start Dioptra. | The main window opens without an error. |
| IQ-2 | Read the installed version from the operating system: Windows Settings → Apps → Installed apps; macOS Finder → Applications → Dioptra → Get Info; Linux `dpkg -s dioptra`, `rpm -q dioptra`, or the AppImage file name. | The approved version (P2). |
| IQ-3 | Help → Dioptra Lab…: enter the license key. | The dialog accepts the key and reports the license as valid. |
| IQ-4 | Records → Run OQ…: let it finish (it also identifies the build). In the result, read Build and Fixture set. | Build shows the approved version and the target of the installer (`x86_64-pc-windows-msvc`, `aarch64-apple-darwin`, `x86_64-apple-darwin` or `x86_64-unknown-linux-gnu`). Record the fixture-set SHA-256; it is identical on every installation of one version. |
| IQ-5 | Locate the configuration directory (Windows `%APPDATA%\io.github.zahakj.dioptra`, macOS `~/Library/Application Support/io.github.zahakj.dioptra`, Linux `~/.config/io.github.zahakj.dioptra`). | It exists after IQ-3 and holds `license.key`. Record its path; `lab-users.json` is created there when users are set up. |
| IQ-6 | Confirm the storage location for regulated project files and its access control, backup and retention, per the customer's procedures. | Location and procedure IDs recorded. |

IQ-4 runs the automated OQ; its full execution and acceptance belong to the
[OQ protocol](oq-protocol.md). Here it identifies the build only.
