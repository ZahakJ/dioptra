# 05 - NIST StRD and the oracle fixtures

How Dioptra knows its numbers are right. Two kinds of reference data live in
`fixtures/`:

- `fixtures/nist/`: the NIST Statistical Reference Datasets, with values
  certified by NIST using multiple-precision arithmetic. These are the ground
  truth for the numerical core: least squares, nonlinear fitting, ANOVA sums
  of squares, mean and SD.
- `fixtures/oracle/`: everything else Prism computes (tests, p-values,
  post hoc comparisons, survival, ROC, distributions). These are generated by
  scripts from SciPy, statsmodels, lifelines and scikit-learn, from our own
  implementations of published formulas, and from 32-digit mpmath references.

An oracle can only be trusted as far as it is checked, so every family that
could be cross-checked was: two libraries against each other, or a library
against a hand-written formula. The generator asserts each check and stops if
one fails (see "What is cross-checked" below).

## 1. NIST StRD

Source: https://www.itl.nist.gov/div898/strd/ . 58 datasets in four classes.
Each has the original `.dat` file and a parsed `<name>.json` next to it, plus
`index.json` with name, class and difficulty.

| Class | Sets | Certified values |
|---|---|---|
| Nonlinear regression (27) | Misra1a, Chwirut2, Chwirut1, Lanczos3, Gauss1, Gauss2, DanWood, Misra1b (lower); Kirby2, Hahn1, Nelson, MGH17, Lanczos1, Lanczos2, Gauss3, Misra1c, Misra1d, Roszman1, ENSO (average); MGH09, Thurber, BoxBOD, Rat42, MGH10, Eckerle4, Rat43, Bennett5 (higher) | parameters and their standard deviations, residual SS, residual SD, df. **11 significant digits.** Two starting points per set. |
| Linear regression (11) | Norris, Pontius (lower); NoInt1, NoInt2 (average); Filip, Longley, Wampler1-5 (higher) | parameters, their SDs, residual SD, R^2, the ANOVA table (SS, MS, F). **15 significant digits.** |
| One-way ANOVA (11) | SiRstv, SmLs01-03 (lower); SmLs04-06, AtmWtAg (average); SmLs07-09 (higher) | between/within df, SS, MS, F, R^2, residual SD. **15 digits.** |
| Univariate (9) | PiDigits, Lottery, Lew, Mavro, Michelso, NumAcc1 (lower); NumAcc2-3 (average); NumAcc4 (higher) | mean, SD (n-1), lag-1 autocorrelation. 15 digits, or exact. |

The difficulty comes from the data, not the model. SmLs07-09 have 13 constant
leading digits, so a one-pass sum-of-squares formula loses everything. NumAcc4
is 10000000.2 +/- 0.1. Filip is a degree-10 polynomial whose normal equations
are hopelessly ill-conditioned, so only QR (or better) survives. MGH09, MGH10
and Bennett5 have long curved valleys that defeat a naive Gauss-Newton.

### JSON layout

All classes share `name`, `class`, `difficulty`, `source_url`, `dat_file`,
`n_observations` and `data` (columns by name). Every certified number appears
twice: as a JSON float and as the exact text NIST printed (`certified_text`,
`std_dev_text`, or `{"value", "text"}` pairs), so no digit is lost.

- **Nonlinear** sets add `equation`, `parameters[]` (`name`, `start1`,
  `start2`, `certified`, `std_dev`), `residual_sum_of_squares`,
  `residual_std_dev`, `degrees_of_freedom`, `predictors`, `model_text` (NIST's
  own wording) and `response_transform`.
  - `equation` uses a small grammar the Rust harness can parse: numbers, `x`
    (or `x1`, `x2`), `b1..b9`, `pi`, `+ - * /`, `^` (power, right
    associative), unary minus, and `exp log sin cos atan sqrt`.
  - The parser checks every equation by evaluating the residual SS at the
    certified parameters and comparing it with the certified RSS (relative
    1e-6, or an absolute check for Lanczos1, whose RSS is 1.4e-25).
  - **Nelson** is fitted to `log(y)` (`response_transform: "log"`) with two
    predictors. Fitting `y` gives wrong answers.
- **Linear** sets add `model` (`{"kind": "polynomial", "degree", "intercept"}`
  or `{"kind": "multiple", "predictors": 6}` for Longley), `parameters[]`,
  `residual_std_dev`, `r_squared` and `anova`. The design matrix for a
  polynomial set is `[1, x, x^2, ...]`. NoInt1/2 have no intercept, so their R^2
  is the uncentred one. Wampler1's F is printed by NIST as "Infinity" and is
  stored as `null` with the text kept.
- **ANOVA** sets have `data.group` (integer labels) and `data.y`, plus
  `between`, `within`, `r_squared`, `residual_std_dev`.
- **Univariate** sets have `data.y` and `certified.{mean, sd_n_minus_1,
  lag1_autocorrelation}`.

Michelso.dat omits its difficulty line. The NIST index lists it as lower, and
the parser applies that.

### Scoring: the log relative error (LRE)

NIST results are scored the way McCullough (1998, *The American Statistician*
52:358, doi:10.1080/00031305.1998.10480590) scored statistical packages:

    LRE = -log10( |q - c| / |c| )      if c != 0
    LRE = -log10( |q| )                if c == 0   (log absolute error)

where q is our value and c the certified one. LRE is roughly "the number of
correct significant digits". Cap it at the number of certified digits (11 for
nonlinear, 15 otherwise), and treat q == c as the cap. An LRE below 1 counts
as 0, a failure.

Minimum LRE the Rust test suite should enforce:

| Class | Lower | Average | Higher | Notes |
|---|---|---|---|---|
| Univariate mean | 14 | 14 | 14 | Easy with any summation. |
| Univariate SD | 13 | 10 | 8 | Needs two passes (or Welford). A one-pass formula scores 0 on NumAcc3-4. |
| Lag-1 autocorrelation | 12 | 9 | 7 | Centre first. |
| ANOVA SS, MS, F, R^2 | 12 | 9 | 7 | SmLs07-09 need centred sums; AtmWtAg is "average" but has 7 constant digits. |
| Linear: coefficients, SDs, residual SD, R^2 | 12 | 12 | 7 | Higher: Longley >= 10, Wampler1-5 >= 8 (Wampler1 residual SD is 0: absolute error <= 1e-10), **Filip >= 7** (Householder QR with column pivoting gets about 7-8; normal equations get 0). |
| Nonlinear: parameters | 6 | 6 | 4 | From **both** starting points. 6 and 4 are minimums; MINPACK-quality LM reaches 7-10 on most sets. |
| Nonlinear: parameter SDs | 4 | 4 | 3 | Asymptotic SEs from the Jacobian at the solution. |
| Nonlinear: residual SS | 8 | 8 | 6 | |

A nonlinear fit that fails to converge from one start is a failure for that
start. It is not a pass with a low LRE, and the test should say which start
failed. MGH09, MGH10, Bennett5 and Eckerle4 from start 1 are the usual
casualties. The fix is the algorithm (scaled LM, geodesic acceleration,
good stopping rules), not the tolerance.

`fixtures/oracle/<test>.json`, one file per family (21 files, about 375 KB
in total, the largest 83 KB):

|---|---|

### File format

```json
{
  "test": "t_tests",
  "reference": "scipy.stats.ttest_ind ...",
  "notes": ["conventions, formulas, sign rules ..."],
  "generator": {"script": "scripts/oracle/gen_fixtures.py", "seed": 20261011, "versions": {"scipy": "1.18.1", "...": "..."}},
  "cases": [
    {"name": "welch/sleep_classic",
     "input": {"x": [...], "y": [...]},
     "expected": {"t": -1.86, "df": 17.78, "p_two_sided": 0.0794, "...": "..."},
     "tolerance": {"rel": 1e-8, "abs": 1e-10, "fields": {"some_key": {"rel": 1e-6, "abs": 1e-7}}},
     "note": "optional"}
  ]
}
```

- **Tolerance rule:** a number passes if `|got - exp| <= abs` **or**
  `|got - exp| <= rel * |exp|`. `fields` overrides the rule for one expected
  key and everything nested under it. Arrays compare elementwise.
- Read the `notes` before writing a test. They define every sign convention
  (difference = x - y, Tukey diff = mean_j - mean_i, HR = group 1 vs group 2),
  which variant a key holds, and how ties and zeros are handled.
- Numbers are written with Python `repr` precision (shortest round-trip), so
  parsing them gives back the exact double. Non-finite values are the strings
  `"Infinity"`, `"-Infinity"` and `"NaN"`. `null` means "not defined for this
  input" (for example, a geometric mean of data with negatives).
- Integer-valued inputs (counts, tables, events) are JSON integers. Everything
  else is a float.
- Case names that end in `_classic` are hand-entered textbook datasets, so
  the same numbers can be checked in R: `sleep` (Student 1908), `PlantGrowth`,
  the Hollander & Wolfe examples from R's `wilcox.test` and `kruskal.test`
  help pages, Anscombe's quartet I, Gehan's 1965 leukaemia trial, Bland &
  Altman's 1986 PEFR meters, Mendel's peas, and Fisher's tea tasting. Spot
  checks against published R output agree: for example, sleep paired
  t = 4.0621, p = 0.002833; PlantGrowth F = 4.846, p = 0.01591; Gehan log-rank
  chi2 = 16.79; Tukey p for PlantGrowth trt2-trt1 = 0.012.
- `distributions.json` ends with an informational case `scipy_max_rel_err`
  (tolerance 1), which records how far SciPy is from the 32-digit references.
  It is not a test.

### Regenerating

```sh
export ORACLE_PY=/path/to/venv/bin/python     # numpy scipy statsmodels lifelines scikit-learn pandas mpmath
"$ORACLE_PY" -I scripts/oracle/parse_nist.py   # NIST .dat -> .json (seconds)
"$ORACLE_PY" -I scripts/oracle/gen_fixtures.py # all oracle families (about 2 minutes)
```

- Paths are relative to the scripts, so the commands work from any directory.
  The venv is never committed.
- **Determinism.** All synthetic data come from one
  `numpy.random.default_rng(20261011)` stream, consumed in a fixed family
  order. That is why `gen_fixtures.py` always regenerates every family: a
  partial run would shift the data of every later family. Two consecutive runs
  give byte-identical files (checked). A change of library version can move
  the last digits of a library-derived value, and `generator.versions`
  records what produced each file. Treat a diff after an upgrade as a review
  item, not as noise.
- `mpmath` is required. It was added to the oracle venv for the 32-digit
  references. scikit-posthocs is not installed, so Dunn's test is implemented
  directly from Dunn (1964).
- Each file is checked to load as JSON and to be under 400 KB. The whole set
  must stay under 6 MB.

### What is cross-checked

The generator asserts each of these on every run:

- f_oneway F equals our SS partition. Welch and Brown-Forsythe match our
  formulas against statsmodels `anova_oneway`.
- The Greenhouse-Geisser epsilon from orthonormal contrasts equals the Box
  double-centred formula.
- Tukey p from `studentized_range` equals `scipy.stats.tukey_hsd`. The
  studentized range cdf agrees with an independent double integral to 1e-12.
- Our Dunnett double integral agrees with `scipy.stats.dunnett` (QMC) to
  2e-3.
- The r x c Fisher enumeration reproduces `fisher_exact` on a 2x2. Woolf and
  Katz CIs match statsmodels `Table2x2` and SciPy `relative_risk`.
- `linregress` matches statsmodels OLS.
- KM survival and log-log CIs match lifelines. Our Mantel-Haenszel chi2
  matches `logrank_test`.
- DeLong's AUC equals `roc_auc_score`. PCA eigenvalues equal the eigenvalues
  of the correlation matrix.
- Each nonlinear optimum is reached from two starts (to 1e-7 relative).
- The 32-digit incomplete beta and gamma agree with mpmath's own `betainc` and
  `gammainc`. The noncentral-t reference agrees with a second integral
  representation.

## 3. Tolerance policy

The tolerances stored in the fixtures are the defaults the Rust tests should
use. The table explains them. A tolerance should be tightened when the Rust
code beats it, and loosened only with a written reason.

| Family | Values | Tolerance | Why |
|---|---|---|---|
| Closed-form arithmetic (descriptive, p-adjust, Bland-Altman, contingency counts) | everything | rel 1e-12, abs 1e-14 | Summation order only. Use compensated or two-pass sums. |
| Test statistics (t, F, U, W, H, chi2, z, r, rho, tau) | statistic | rel 1e-10 (fixtures store 1e-8 or 1e-9) | Same formula, different summation. |
| p-values in the body (p > 1e-6) | p | rel 1e-8 **or** abs 1e-10 | Special-function accuracy is about 1e-14. The slack covers formula variants such as tie corrections. |
| p-values in the tails (p < 1e-6) | p | rel 1e-6 | Relative error matters there. Never compute 1 - cdf. Compare log p if p < 1e-300. |
| Exact discrete p (Mann-Whitney, Wilcoxon, Fisher, Spearman/Kendall exact, runs) | p | rel 1e-12 (fixtures store the family default 1e-8; tighten in the test) | Rational counts. Any larger error is a bug. |
| Distribution functions (`distributions.json`) | cdf, sf, pdf | rel 1e-13 (normal) to 1e-12 | Expected values are correctly rounded doubles. |
| | ppf, isf | rel 1e-12 | Newton/Halley polish against the 32-digit cdf. |
| | noncentral t | rel 1e-10 | Even the reference needs quadrature. |
| Studentized range | cdf, sf | rel 1e-7, abs 1e-11 | The reference is SciPy's quadrature, independently confirmed to about 1e-12. 1e-7 leaves room for Gauss-Legendre implementations of the AS 190 kind. |
| | ppf | rel 1e-7 | |
| Tukey / Dunnett adjusted p | p | rel 1e-7, abs 1e-9 | These rest on studentized range and multivariate-t integrals. |
| SciPy Dunnett (QMC), statsmodels Tukey `qsturng` | p | abs 2e-3 | Kept only as sanity checks. |
| Shapiro-Wilk | W, p | rel 1e-7 / 1e-6 | AS R94 coefficients are single-precision polynomial fits, so match the algorithm, not more digits than it has. |
| Lilliefors | p | rel 1e-6 | Table interpolation. Prism's Dallal-Wilkinson differs at p > 0.1. |
| Linear regression | all | rel 1e-9 | QR versus normal equations differ at about 1e-12 on well-conditioned data. |
| Nonlinear regression | params, SE, CI | rel 1e-6 | The optimum is polished, but SEs come from a central-difference Jacobian. |
| | SS, Sy.x, AICc, R^2 | rel 1e-9 | Objective values are flat at the optimum. |
| | robust fits | rel 1e-5 | Non-smooth loss, flatter optimum. |
| Survival | KM, CIs, log-rank | rel 1e-9 | |
| | Cox | rel 1e-6 | Iterative Newton-Raphson. |
| ROC, PCA | all | rel 1e-9 to 1e-10 | PCA: apply the sign rule from `notes` before comparing. |
| Outliers | flagged indices | exact | |
| | ROUT robust centre | rel 1e-9 | 1-D minimisation, converged to 1e-13. |

**When an expected value is 0:** relative error is meaningless, so the `abs`
term decides. All fixture tolerances carry an `abs`.

**When Prism and the oracle disagree by convention** (quartile method,
Lilliefors p, Wilson versus Wilson-Brown CIs, Katz versus Koopman RR CI), the
fixture holds the textbook or library value under an explicit name.
Prism-specific variants become separate keys when we add them. A tolerance
must never be widened to paper over a convention difference.

### Known limits of the oracle

- **Profile-likelihood CIs** for nonlinear fits (Prism's "asymmetric CI") are
  not in this batch. Only asymptotic CIs are.
- **ROUT for curves:** only the "fit a constant" case is generated. The curve
  case needs the adaptive-RSDR robust fit, and SciPy's fixed-scale Cauchy loss
  is not the same thing (`robust/*` cases record `f_scale`).
- **Fisher exact on r x c** is computed by full enumeration, so only small
  tables are included (at most 205 tables). FEXACT-scale tables need
  reference values from R.
- **Hazard ratios:** the Cox HR uses Efron ties. Breslow ties (Prism's Cox
  module may use them) would need another reference.
- **Two SciPy defects** were found while building the distribution tables:
  `stats.f.isf` far upper tail, and `stats.nct.cdf` far lower tail (see
  `research/04-algorithms.md` section 21). The fixtures use 32-digit
  references, so these do not leak into the expected values.
